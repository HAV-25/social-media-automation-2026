# Current architecture archive — v0.9.0

**Version:** `v0.9.0-current-architecture.20260811`

**Archive date:** 2026-08-11

**Archive branch:** `archive/current-architecture-v0.9.0-20260811`

**Purpose:** Preserve the complete application immediately before development of the lightweight architecture.

## Included architecture

- Next.js application for authentication, brand workspaces, editorial review, operations, and downloads.
- Next.js server APIs for workflow contracts, AI/provider calls, state changes, image composition, and recovery.
- Supabase PostgreSQL, Auth, Storage, RLS, durable state, provenance, costs, and audit history.
- Ten n8n workflows for intake, normalization, scoring, research, generation, verification, images, regeneration, and recovery.
- OpenAI provider adapters and versioned prompts.
- Deterministic 1200×630 branded-image composition and final-layout validation.

## Deployment dependencies

- The browser and n8n workflows depend on the deployed Next.js application.
- Supabase supplies the durable database, authentication, and private asset storage.
- The self-hosted n8n instance supplies scheduled and asynchronous orchestration.
- OpenAI credentials are required only for credentialed research, writing, verification, and image generation.
- `WORKFLOW_HMAC_SECRET` and the documented workflow environment are required by both the application and n8n.

## Known limitations at archive time

- Workflow execution depends on the deployed Next.js APIs; a Netlify outage can stop RSS-to-package processing.
- The ten-workflow chain and synchronous application boundaries have required repeated compatibility and recovery corrections.
- Production workflow state must be reconciled against durable Supabase records because successful n8n payload retention is intentionally limited.
- A production-like end-to-end run still depends on external Supabase, n8n, OpenAI, RSS, and hosting availability.
- The lightweight architecture is intended to remove the application deployment from the daily automation execution path; it is not part of this archive.

## Database and workflow position

- All committed Supabase migrations under `supabase/migrations` belong to this version.
- All committed workflow exports under `n8n/workflows` belong to this version.
- Production database and n8n environments remain external systems. Restoring this source snapshot does not automatically roll those systems back.
- Before any production restoration, compare the deployed migration ledger and n8n workflow versions with this tag and use a forward-fix where data has advanced.

## Restoration

Create a separate working branch from the immutable tag:

```text
git fetch origin --tags
git switch -c restore/current-architecture-v0.9.0 v0.9.0-current-architecture.20260811
pnpm install --frozen-lockfile
pnpm check
```

Do not force-move the tag or overwrite `main`. Configure a separate environment from `.env.example`, verify Supabase migrations and RLS, import the tagged n8n workflow JSON, and run the UAT smoke journey before directing users to a restored deployment.

## Security and product boundaries

- No secrets or credential IDs are included in the archive.
- Supabase remains the durable system of record.
- Human approval remains required before content leaves the platform.
- This version contains no social publishing or scheduling integration.
